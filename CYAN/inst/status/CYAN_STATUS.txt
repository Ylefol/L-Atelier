cyan_reditools.R:
-----------------
CYAN_run_reditools(bam, reference, output_dir, work_dir, sample_name,
                   strand_mode, min_coverage, min_base_quality,
                   min_read_quality, min_read_length, min_edits, strict,
                   region, omopolymeric_file, splicing_file, bed_file,
                   require_dup_marked, keep_tmp, save_rds, verbose)
  - Detects RNA editing events via REDItools2 (Python, basilisk env)
  - Defaults match REDItools2 native defaults (min_coverage=1, min_edits=0,
    strict=FALSE) — full unfiltered output returned for post-hoc filtering
  - Validates inputs, creates dirs, builds CLI args, runs via system2
  - require_dup_marked=TRUE (default): hard-stops before running REDItools2
    unless the BAM has >=1 read flagged as a duplicate (SAM FLAG 0x400) --
    reditools.py's own duplicate filter (read.is_duplicate) only excludes
    reads that already carry this flag, so a BAM that was never run through
    samtools markdup / Picard MarkDuplicates makes that filter a silent
    no-op. Set FALSE to skip (e.g. a BAM confidently known to be dup-free).
    Skipped entirely on a checkpoint cache-hit (no filtering happens then).
  - Checkpoint behaviour: skips REDItools2 if raw output already exists
  - Parses REDItools2 tab-delimited output → cyan_editing_result data.frame
  - Saves three files to output_dir: full .txt checkpoint, subs-only .txt,
    optional .rds
  - Cleans work_dir intermediates if keep_tmp = FALSE
  - Returns: cyan_editing_result (data.frame + params attribute)

.cyan_check_duplicates_marked(bam, max_reads = 5e6, verbose)  [internal]
  - Scans a BAM for the SAM duplicate flag via inst/python/check_duplicates.py
    (basilisk env, same cyan_reditools_env as REDItools2 itself -- pysam
    already pinned there, no new dependency)
  - Exits on the first duplicate-flagged read found; capped at max_reads for
    a genuinely duplicate-free BAM
  - Used by CYAN_run_reditools()'s require_dup_marked check

print.cyan_editing_result(x, ...)
  - S3 print method: shows n positions, n with substitutions, freq range

CYAN_run_reditools_batch(bam, reference, output_dir, ..., verbose)
  - Batch wrapper: iterates over a vector of BAM paths
  - Named vector → names forwarded as sample_name (controls output file prefixes)
  - Unnamed vector → sample names derived from BAM filenames as usual
  - Per-sample error handling: failed samples warn and record NULL; batch continues
  - Checkpoint behaviour inherited: re-run skips already-completed samples
  - Returns: cyan_batch_result (named list of cyan_editing_result / NULL)

print.cyan_batch_result(x, ...)
  - S3 print method: shows succeeded/failed counts + per-sample position summary

cyan_germline_variants.R:
--------------------------
CYAN_flag_germline_variants(rna_result, dna_bam, reference, output_dir,
                            work_dir, sample_name, dna_min_coverage,
                            dna_min_alt_reads, dna_min_alt_freq,
                            require_dup_marked, keep_tmp, save_rds, verbose,
                            debug, ...)
  - Cross-references confident RNA-editing candidates (substitution-carrying
    rows of a cyan_editing_result) against matched WGS data from the same
    individual, to separate true editing from germline variants relative to
    the reference genome
  - Does NOT reimplement DNA-seq calling: reuses CYAN_run_reditools() itself
    as the pileup engine for dna_bam, restricted via bed_file to exactly the
    RNA-candidate positions, with strand_mode=0 and strict=FALSE (reference-
    only rows must be reported too, or "no row" is ambiguous between
    "uncovered" and "no variant")
  - Entirely optional / additive: CYAN_run_reditools() and
    CYAN_run_reditools_batch() are completely untouched by this, so an
    RNA-only workflow with no matched WGS data is unaffected
  - Per-position primary alt base resolved from AllSubs (highest RNA-read-
    supported alt, via internal .cyan_primary_alt_base()), then classified
    from the WGS pileup as "germline" / "confirmed_somatic" / "undetermined"
    (WGS coverage too thin to call) -- tagged via a new germline_status
    column, never silently dropped
  - dna_min_coverage=10L / dna_min_alt_reads=3L / dna_min_alt_freq=0.1
    default to the original REDItools' REDItoolDnaRna.py conventions
    (-c 10, -v 3, -N 0.1) for this exact DNA/RNA comparison -- carried over,
    not independently re-derived; verify before treating as settled
  - Returns: rna_result + 4 new columns (dna_coverage, dna_alt_reads,
    dna_alt_freq, germline_status); germline call params attached as a
    separate germline_params attribute (rna_result's own params attribute
    is left untouched)
  - Outputs to output_dir: {sample}_germline_flagged.txt (candidates table),
    optional {sample}_germline_flagged.rds

.cyan_primary_alt_base(reference, all_subs, count_A, count_C, count_G, count_T)  [internal]
  - Resolves AllSubs (possibly multi-code, e.g. "AG AC") to the single
    highest-read-supported alt base among codes matching the reference

.cyan_write_bed(region, position, path)  [internal]
  - Writes deduped, sorted 0-based half-open BED from a position table

CYAN_flag_germline_variants_batch(rna_results, dna_bam, reference,
                                  output_dir, ..., verbose)
  - Batch wrapper: dna_bam is a named vector (names = animal IDs), only
    needs entries for animals that actually have matched WGS -- samples
    without one are simply absent, no special-casing required
  - Per-sample error handling + cyan_batch_result return, same pattern as
    CYAN_run_reditools_batch()
