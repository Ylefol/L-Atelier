# GAIA R Package Restructure Plan

## Overview

Convert ZERO_DAWN/GAIA from a collection of `source()`-able scripts into a proper R package. This gives us:
- `?function_name` help in Positron
- `library(GAIA)` replaces all `source()` calls
- Lazy loading (functions available without memory cost until called)
- Tab completion on `MODULE_` prefixes
- Proper namespace (internal helpers hidden, only public API exported)

---

## Current State

- **9 modules**, **58 R files** (excluding 2 legacy), **~35,800 lines of code**
- ~130 exported functions (MODULE_ prefixed)
- ~40 internal helpers (dot-prefixed)
- 12 S3 classes with print methods
- 7 inter-module `source()` calls to eliminate
- 30+ external package dependencies
- Roxygen2 coverage: ~98% (nearly all public functions documented)
- 2 legacy files to remove (ConvCCA_old.R, RelPMDCCA_old.R)
- `export_shared.R` provides shared helpers sourced by multiple Eleuthia export modules
  (resolves naturally in package — all in same namespace)

### Imports vs Suggests Strategy

**Imports** (always needed, loaded with the package):
- `stats`, `grDevices`, `utils` — base R packages used everywhere
- `ggplot2` — used by nearly every Aether function
- `circlize`, `ComplexHeatmap`, `grid` — used by circos (core feature)

**Suggests** (checked at runtime with `requireNamespace()`):
- All Bioconductor packages (DESeq2, GenomicRanges, WGCNA, etc.)
- Domain-specific CRAN packages (FactoMineR, grpreg, pheatmap, etc.)
- Interactive viz (plotly, visNetwork, htmlwidgets)

This means `library(GAIA)` loads fast. Heavy dependencies are only needed when calling
specific functions, and the existing `requireNamespace()` / `library()` checks in
functions handle this.

## Development Workflow (Post-Migration)

```r
# During development (replaces source() calls):
devtools::load_all("path/to/GAIA")

# After modifying roxygen2 docs:
devtools::document("path/to/GAIA")

# In project scripts:
library(GAIA)

# Check package health:
devtools::check("path/to/GAIA")
```

---

## Risk Mitigation

- **Work in parallel**: Build `GAIA_pkg/` alongside existing `GAIA/` — don't disrupt
  current workflows until verified
- **Module-by-module**: Migrate and test one module at a time, following dependency order
- **Git branch**: Do all restructuring on a dedicated branch
- **Project script testing**: After each module migration, test with existing project
  scripts (Solveig, etc.)
- **CIBERSORT**: The `source(cibersort_path, local = TRUE)` pattern is intentional and
  stays — it sources user-provided external code, not a GAIA module

---

## Estimated Effort

- Phase 1 (skeleton): Quick — mostly boilerplate
- Phase 2 (file migration): Bulk of the work — 58 files to copy, rename, and clean
- Phase 3 (roxygen2): Moderate — most docs exist, mainly removing library() and adding
  @importFrom
- Phase 4 (verify): Iterative — fix issues as R CMD check finds them
- Phase 5 (cleanup): Quick — rename directories, update docs

The actual function code barely changes. The effort is primarily:
1. Removing `source()` and `library()` lines
2. Adding `requireNamespace()` or `pkg::function()` patterns for optional deps
3. Ensuring roxygen2 `@export` and `@method` tags are correct
4. Running `devtools::check()` until clean
