concat_lanes.R:
----------------
HORIZON_concat_lanes(fastq_r1, fastq_r2=NULL, output_dir, sample_id, force=FALSE)
  - Merges multi-lane/multi-flowcell FASTQs into one R1 (+ R2) file per sample
  - Byte-level concatenation of raw .fastq.gz files (no decompress/recompress)
    -- valid because gzip files are independent concatenable "members" (RFC
    1952); every downstream reader here (Rfastp, Rsubread, zcat) handles
    multi-member gzip transparently
  - Needed for HORIZON_run_qc_trim()/HORIZON_run_align(), which each expect
    exactly one FASTQ per sample per read direction (unlike
    HORIZON_run_salmon(), which accepts lane vectors natively)
  - fastq_r1[i]/fastq_r2[i] must be positionally matched (same lane)
  - Output: <output_dir>/<sample_id>_R1.fastq.gz (+ _R2.fastq.gz)

.horizon_concat_bytes(input_files, output_file)  [internal]
  - Raw readBin/writeBin byte-stream concatenation used by
    HORIZON_concat_lanes()

build_index.R:
--------------
HORIZON_build_index(basename, reference, memory=8000, index_split=TRUE,
                    gapped=TRUE, force=FALSE, ...)
  - Wraps Rsubread::buildindex()
  - Skips build if index files already exist at basename (force=FALSE default)

----------

  - NULL blacklist_bed -> warn and return current BAM unchanged

peak_calling.R:
---------------
HORIZON_call_peaks(treatment_bed, control_bed=NULL, output_dir,
                   sample_name, genome_size="hs", q_value=0.05,
                   broad=FALSE, nomodel=FALSE, shift=NULL,
                   extsize=NULL, extra_flags=character(0))
  - macs3 callpeak via .horizon_run_cli (user conda env)
  - nomodel/shift/extsize: replaces old assay_type enum; user-controlled
  - Recommended: ATAC nomodel=TRUE shift=-100 extsize=200;
    ChIP-TF defaults; ChIP-histone broad=TRUE;
    CUT&RUN/CUT&TAG nomodel=TRUE
  - Warns if shift/extsize set without nomodel=TRUE
  - Output: <sample_name>_peaks.narrowPeak (or .broadPeak)

HORIZON_call_peaks_seacr(treatment_bed, control_bed=NULL, output_dir,
                          sample_name, chrom_sizes, threshold=0.05,
                          normalize="non", stringency="stringent",
                          force=FALSE, verbose=TRUE)
  - Pure-R reimplementation of SEACR (Meers et al. 2019, doi:10.1186/s13072-019-0287-4)
  - No conda dependency — uses GenomicRanges/IRanges only
  - Mirrors HORIZON_call_peaks interface (same core args: treatment_bed,
    control_bed, output_dir, sample_name)
  - chrom_sizes: data.frame(chr, size) from HORIZON_get_chrom_sizes()
  - threshold: top fraction of blocks by AUC when no control (default 0.05)
  - normalize: "non" (raw counts) or "norm" (per-million)
  - stringency: "stringent" (AUC AND max_signal) or "relaxed" (either)
  - Output: <sample_name>_seacr_peaks.bed with peak_id, chr, start, end,
    total_signal, max_signal columns
  - Validate results against original SEACR tool before publication use

star_align.R:
-------------
HORIZON_build_star_index(genome_fasta, gtf, index_dir,
                          sjdb_overhang=100L, threads=8L,
                          extra_flags=character(0), force=FALSE)
  - Wraps STAR --runMode genomeGenerate (directory-based index, not a
    basename-prefix index like Rsubread/Salmon)
  - sjdb_overhang should be (actual FASTQ read length - 1) for the run this
    index is used for; the 100L default is a general-purpose placeholder,
    not verified against any specific run's read length
  - Skips rebuild if <index_dir>/SAindex exists (force=TRUE to override)
  - Uses .horizon_run_cli("STAR", args) (Mechanism A) -- STAR shares the
    standard horizon_cli env, registered via HORIZON_set_conda_env()

HORIZON_run_star_align(sample_sheet, sample_id, index,
                        use_trimmed=TRUE, threads=8L,
                        outfilter_multimap_nmax=100L,
                        win_anchor_multimap_nmax=100L,
                        tmp_dir=NULL,
                        force=FALSE, verbose=TRUE, ...)
  - Separate alignment path from HORIZON_run_align() (Rsubread); both can
    coexist per sample (aligned/ vs aligned_star/ subfolders)
  - Relaxed multi-mapping filter (STAR default outFilterMultimapNmax=10
    would silently drop reads mapping to >10 loci) -- needed so
    HORIZON_run_tecount() can redistribute multi-mapping reads across TE
    loci instead of losing them; 100/100 is the value cited in the
    TEtranscripts tutorial, not independently re-derived here
  - Outputs coordinate-sorted BAM directly (--outSAMtype BAM
    SortedByCoordinate); renamed to <sample_id>_sorted.bam and indexed via
    Rsamtools::indexBam() (no separate HORIZON_sort_index_bam() call needed)
  - --outTmpDir explicitly redirected to tempdir()/STARtmp_<sample_id> (or
    tmp_dir if given), never left at STAR's own default of
    <outFileNamePrefix>_STARtmp -- that default sits under output_dir, and
    STAR uses a FIFO there for --readFilesCommand zcat, which fails with
    "could not create FIFO file" when output_dir is on an exFAT/NTFS-mounted
    drive (hit in practice: ADAM's output_dir is on an exFAT-mounted external
    drive). tempdir() is always on the local filesystem regardless of where
    output_dir points. Confirmed against `STAR --help`: STAR fully
    clears/manages the tmp dir itself, so handing it a fresh subdirectory is
    safe.
  - Uses .horizon_run_cli("STAR", args) (Mechanism A, like salmon.R) --
    confirmed no dependency conflict with the existing horizon_cli tools
    (samtools/bedtools/macs3/deeptools/salmon), so no dedicated env needed
    (unlike split-pipe, which genuinely does conflict -- see parse.R)
  - Output: <output_dir>/<sample_id>/aligned_star/<sample_id>_sorted.bam

tetranscripts.R:
----------------
HORIZON_run_tecount(sample_sheet=NULL, sample_id=NULL, bam_file=NULL,
                     output_dir=NULL, strandedness=NULL, gene_gtf, te_gtf,
                     mode="multi", force=FALSE, verbose=TRUE, ...)
  - Uses .horizon_run_cli("TEcount", args) (Mechanism A) -- shares the
    standard horizon_cli env with STAR, registered via
    HORIZON_set_conda_env()
  - Wraps TEcount (bundled with bioconda `tetranscripts`, NOT the 2-group
    TEtranscripts DE binary -- TEcount quantifies one BAM at a time, no
    treatment/control framing, which is what allows use with designs of
    more than 2 conditions)
  - Requires a STAR BAM with multi-mapping alignments reported (see
    HORIZON_run_star_align()), never the Rsubread BAM
  - mode="multi" (default): EM-based redistribution of multi-mapping reads
    across TE loci -- the actual point of using this over featureCounts on
    a RepeatMasker GTF directly. mode="uniq": unique-mapping reads only.
  - Only the TE rows of its output are meant to be used downstream (see
    HORIZON_aggregate_tecount()) -- gene rows come from a different
    aligner/counter than the project's canonical gene-level counts and
    would be inconsistent with them if mixed in
  - Flag names (-b/--GTF/--TE/--mode/--stranded/--sortByPos/--project/
    --outdir) confirmed against a real `TEcount --help` (2026-07-28).
    --stranded takes no/forward/reverse (corrected from an initial
    no/yes/reverse guess -- see .strand_to_tecount() below)
  - Output: <output_dir>/<sample_id>/tecount/<sample_id>.cntTable

HORIZON_aggregate_tecount(sample_sheet, te_gtf, output_root=NULL,
                          save_rds=TRUE, save_metadata=TRUE)
  - Builds TE-subfamily x samples count matrix from per-sample cntTable
    files, keeping TE rows only (gene rows dropped)
  - TE rows identified by cross-referencing against the ground-truth
    composite ID set (gene_id:family_id:class_id) parsed directly from
    te_gtf via rtracklayer, not a hardcoded ID-format assumption
  - Writes te_count_matrix.csv, te_count_matrix.rds, sample_metadata.csv

HORIZON_merge_gene_te_counts(gene_counts, te_counts, verbose=TRUE)
  - rbind's a canonical gene-level count matrix (e.g. from
    HORIZON_aggregate_counts()) onto a TE count matrix (from
    HORIZON_aggregate_tecount()) into one feature x sample matrix, ready
    for ARTEMIS_normalize_counts()
  - Errors on any rowname collision between the two inputs; intersects
    colnames (samples), warning on any sample present in only one input
  - Fills a genuine gap: no prior HORIZON/GAIA convention combined two
    distinct feature sets (only combining samples for one feature set
    had precedent, e.g. HORIZON_aggregate_counts's per-sample cbind)

  - Parses a RepeatMasker-derived TE GTF via rtracklayer::import() and

HORIZON_validate_parse_sheet(path, check_files = TRUE)

HORIZON_run_splitpipe(sample_sheet, run_id, sample_layout, conda_env,
                      mode="all", threads=8L, force=FALSE,
                      kit_score_skip=FALSE, verbose=TRUE, ...)
  - Wraps split-pipe CLI; supports single-cell and single-nucleus RNA-seq
  - sample_layout: named character vector mapping sample names to well ranges
    e.g. c(control="A1-B6", treatment="C1-D6") or c(all_cells="A1-D12")
  - conda_env: explicit path to conda env containing split-pipe
    (cannot share horizon_cli due to Python dependency conflicts)
    Install: conda create -n parse_env python=3.10 && pip install parsebiosciences
  - mode="all": demux + align + count in one pass; "split"/"count" for sub-steps
  - kit_score_skip=FALSE: set TRUE to pass --kit_score_skip (bypass barcode check)
  - verbose=TRUE: prints full split-pipe command before executing
  - Output: output_dir/run_id/ (split-pipe internal structure, DGE matrix per sample)
  - Output is compatible with TALARIA_load_parse() in CAULDRON (planned)
  - force=FALSE: skip if output directory already exists

HORIZON_run_parse_velocity(sample_sheet, conda_env, cell_metadata_path,
                            output_file=NULL, force=FALSE)
  - Generates spliced/unspliced AnnData from split-pipe tscp_assignment.csv files
  - Calls inst/python/parse_velocity.py via system2(conda_env/bin/python)
  - working_dir inferred from sample_sheet$output_dir (must be consistent across rows)
  - run_ids taken from sample_sheet$run_id; tscp paths: output_dir/run_id/process/tscp_assignment.csv
  - tscp files auto-decompressed in-place (gunzip) if .csv.gz found; no manual step needed
  - cell_metadata_path: combined split-pipe cell_metadata.csv (for cell filtering)
  - output_file defaults to output_dir/adata_vel.h5ad
  - Same conda_env as HORIZON_run_splitpipe (split-pipe + scvelo/scanpy/dask)
  - Output: adata_vel.h5ad with spliced/unspliced layers + cell metadata; load in CAULDRON

HORIZON_combine_splitpipe(sample_sheet, conda_env, output_subdir="combined",
                           force=FALSE, verbose=TRUE)
  - Wraps split-pipe --mode comb to merge all per-run outputs into one dataset
  - sublib_dirs: output_dir/run_id/ for each run; validates all exist before running
  - output_subdir: combined output written to output_dir/combined/ (default)
  - Combined output provides cell_metadata.csv required by HORIZON_run_parse_velocity
  - verbose=TRUE: prints full command; force=FALSE: skips if combined dir exists
