annotation.R:
-------------
APOLLO_get_chr_mapping(genome)
  - Get chromosome name mapping for specific genome
  - Currently supports: "T2T" (T2T-CHM13v2.0)
  - Returns named vector: NCBI accession -> UCSC name

APOLLO_get_chromosome_sizes(annotation_path, chromosomes, name_mapping,
                             add_chr_prefix, cache_dir, cache_name, force, verbose)
  - Extract chromosome sizes from GTF/GFF annotation
  - Supports gzipped files
  - Uses ##sequence-region pragmas if available (GFF3)
  - Caching: saves to ZERO_DAWN/data/ as RDS for fast reload
  - Cache filename includes name_mapping (e.g., _T2T suffix)
  - force=TRUE to regenerate cache
  - Returns data.frame: chr, size

APOLLO_chr_sizes_to_seqinfo(chr_sizes, genome)
  - Convert chr_sizes data.frame to Seqinfo object
  - For compatibility with GenomicRanges/Bioconductor

APOLLO_sequence_composition(regions, fasta_path, chr_mapping, extend, min_width,
                             include_repeats, include_sequence, verbose)
  - Calculate GC/AT content for genomic regions
  - Detects homopolymer runs (e.g., AAAA) and dinucleotide repeats (e.g., ATATAT)
  - chr_mapping: "T2T" or custom vector to translate region chr names to FASTA names
    (e.g., chr1 -> NC_060925.1 for T2T FASTA files)
  - extend: bp to add on EACH side (consistent with ELEUTHIA_expand_regions)
  - min_width: regions below threshold return NA (default 100bp)
  - include_sequence: whether to include sequence column in output (default TRUE)
  - Compatible with ELEUTHIA_select_regions output
  - Returns: gc_percent, at_percent, n_count, repeat statistics, optionally sequence

peak_annotation.R:
------------------
APOLLO_make_txdb(gtf_path, cache_dir, cache_name, chr_mapping, organism,
                  force, verbose)
  - Create TxDb from GTF/GFF annotation file
  - Automatic caching to ZERO_DAWN/data/ as SQLite (uses AnnotationDbi::saveDb)
  - chr_mapping: "T2T" for built-in NCBI->UCSC renaming, or custom named vector
  - Useful for non-standard genomes like T2T-CHM13
  - One-time slow creation, fast subsequent loads

APOLLO_annotate_peaks(regions, txdb, tss_region, level, verbose)
  - Annotate peaks with genomic features using ChIPseeker
  - Returns: annotation (Promoter/Exon/Intron/etc.), gene_id, distance_to_tss
  - Simplified annotation categories for easy filtering
  - Works with any TxDb (including custom T2T)

APOLLO_enrich_go(annotated_peaks, org_db, ont, gene_id_type, pval_cutoff,
                  qval_cutoff, min_gs_size, max_gs_size, verbose)
  - GO enrichment analysis using clusterProfiler
  - Supports BP, MF, CC, or ALL ontologies
  - Auto-converts gene IDs (SYMBOL, ENSEMBL) to ENTREZID
  - Returns enrichResult object (dotplot, barplot, cnetplot methods)

APOLLO_enrich_kegg(annotated_peaks, org_db, organism, gene_id_type,
                    pval_cutoff, qval_cutoff, verbose)
  - KEGG pathway enrichment analysis
  - Same interface as APOLLO_enrich_go

gene_enrichment.R:
------------------
APOLLO_convert_genes(genes, org_db, from_type, to_type, strip_version, verbose)
  - Convert gene IDs with fallback to original when conversion fails
  - Ideal for count matrix rownames (preserves all genes)
  - strip_version: removes Ensembl version suffixes (default TRUE)
  - Unmapped genes keep their (stripped) original ID
  - Handles duplicates by adding suffix (e.g., "TP53.1")
  - Example: rownames(counts) <- APOLLO_convert_genes(rownames(counts), org.Hs.eg.db)

APOLLO_prepare_genelist(genes, org_db, from_type, to_type, strip_version,
                         drop_na, verbose)
  - Convert gene symbols to ENTREZID (or other ID types)
  - Works with single vector or named list (e.g., module gene lists)
  - strip_version: removes Ensembl version suffixes (ENSG00000141510.16 -> ENSG00000141510)
  - org_db can be NULL to just clean IDs without conversion
  - Reports conversion statistics

APOLLO_extract_module_genes(modules, modules_of_interest, exclude_grey,
                             strip_version, org_db, from_type, to_type, verbose)
  - Extract gene lists from wgcna_modules object
  - Uses module_names (module_0, module_1, ...) as list names
  - exclude_grey: excludes module_0 (unassigned genes)
  - strip_version: for Ensembl IDs with version numbers (e.g., for gprofiler)
  - Optionally convert to ENTREZID if org_db provided
  - from_type/to_type: control ID conversion (default ENSEMBL -> ENTREZID)
  - Convenience wrapper for WGCNA workflows

APOLLO_enrich_gost(gene_lists, organism, sources, user_threshold, correction_method,
                    domain_scope, custom_bg, min_term_size, max_term_size, max_query_size,
                    significant, exclude_iea, verbose)
  - Functional enrichment using gprofiler2::gost()
  - Accepts multiple ID types directly (ENSEMBL, SYMBOL, etc.) - no conversion needed
  - Sources: GO:BP, GO:MF, GO:CC, KEGG, REAC (Reactome), WP (WikiPathways),
             TF (TRANSFAC), MIRNA, CORUM, HP (Human Phenotype)
  - Returns combined results with 'module' and 'source' columns
  - Stores module_sizes in metadata for annotation coverage calculation
  - correction_method: "g_SCS" (default), "fdr", "bonferroni"
  - organism: "hsapiens", "mmusculus", etc.

APOLLO_filter_enrichment(enrich_result, sources, modules, top_n)
  - Filter gost_enrichment results by source (e.g., "KEGG") or module
  - top_n: keep top N terms per module per source

APOLLO_rank_from_de(de_result, rank_by, gene_col, verbose)
  - Builds a named ranked gene vector for GSEA from an artemis_limma /
    artemis_ts_de differential expression result

APOLLO_gsea(ranked_genes, gene_sets, species, db_species, collection,
            min_size, max_size, fdr_threshold, verbose)
  - GSEA via fgsea::fgseaMultilevel(); gene_sets=NULL fetches from MSigDB via msigdbr
  - species: full scientific name (e.g. "Homo sapiens"); db_species: NULL (msigdbr
    default, human-centric w/ orthologs) or "MM" for native mouse gene sets
  - collection: MSigDB codes (e.g. "H","C2","C5"); subcollection via colon
    (e.g. "C2:CP:REACTOME", "C5:GO:BP"); mouse-native codes are M-prefixed (MH,M2,M5)
  - Updated 2026-07-17: migrated msigdbr call from deprecated category/subcategory
    args to current collection/subcollection args (installed msigdbr >= 10.0 deprecated
    the old names); added db_species param, previously unexposed, which meant mouse runs
    silently got human-ortholog-mapped gene sets instead of native mouse collections
    unless called with a manually-constructed msigdbr gene_sets list. Mirrors CAULDRON's
    KERAUNOS_gsea(), which was already on the current API.
  - Bugfixed same day: db_species=NULL (the documented default) was passed straight
    through to msigdbr::msigdbr(), which errors ("db_species is not a character
    vector") -- unlike msigdbr_collections(), msigdbr() does not accept NULL and fall
    back to its own default. Now resolved to "HS" locally before the call when NULL.
    Same latent bug existed in (and was fixed in) CAULDRON's KERAUNOS_gsea(),
    KERAUNOS_gsea_pseudobulk(), and KERAUNOS_gsea_markers_pairwise().

APOLLO_get_collectri(organism, split_complexes, verbose)
  - Fetch CollecTRI TF-target network (default for TF activity inference)
  - Comprehensive collection from multiple sources
  - Returns: source (TF), target (gene), mor (mode of regulation)

APOLLO_get_dorothea(organism, levels, verbose)
  - Fetch DoRothEA TF regulons with confidence filtering
  - levels: "A" (highest) to "E" (lowest) - default all
  - Returns: source, target, mor, confidence

APOLLO_get_progeny(organism, top, verbose)
  - Fetch PROGENy pathway-responsive gene signatures
  - top: number of genes per pathway (default 500)
  - 14 cancer-relevant pathways from perturbation experiments
  - Returns: source (pathway), target (gene), weight

APOLLO_list_activity_databases()
  - Print available prior knowledge databases
  - Shows CollecTRI, DoRothEA (TF-target) and PROGENy (pathway)

motif_enrichment.R:
-------------------
APOLLO_homer_motif_enrichment(bed_file, genome, output_dir, size, mask,
                               denovo, denovo_n, bg, nproc, extra_args, verbose)
  - Run HOMER findMotifsGenome.pl on a single BED file
  - Runs inside the .gaia_homer_env basilisk env (bioconda `homer` package;
    updated 2026-07-08, was plain Sys.which()/PATH before). Resolves
    findMotifsGenome.pl from dirname(reticulate::py_exe())'s bin dir via
    .homer_run(), same pattern as CPAT/SignalP/Pfam in isoform_annotation.R
  - NOTE: HOMER still needs a one-time, separate per-genome data install
    (configureHomer.pl -install <genome>) run against .gaia_homer_env before
    a given genome string works -- basilisk only provisions the binary
  - size: region size (default 200, "given" for actual peak widths)
  - mask: mask repeats (default TRUE, recommended for ATAC)
  - denovo: enable de novo discovery (default FALSE, uses -nomotif)
  - bg: optional background BED for custom comparison
  - Parses output and returns homer_motif S3 object

APOLLO_homer_motif_enrichment_batch(bed_files, genome, output_dir, ..., verbose)
  - Run HOMER on multiple peak sets (named character vector)
  - Creates subdirectory per set, iterates single-set function
  - Returns homer_motif_batch S3 object with combined results + summary

APOLLO_load_homer_results(homer_dir, verbose)
  - Parse existing HOMER output directory (re-load without re-running)
  - Parses knownResults.txt (known motif enrichment)
  - Parses homerMotifs.all.motifs (de novo, if available)
  - Returns homer_motif S3 object

APOLLO_load_homer_batch(output_dir, set_names, verbose)
  - Load multiple HOMER result directories into batch object
  - Auto-detects subdirectories containing knownResults.txt
  - Returns homer_motif_batch S3 object

APOLLO_filter_motifs(homer_result, q_thresh, p_thresh, min_target_pct, top_n, verbose)
  - Filter motif results by significance/enrichment thresholds
  - Works on both homer_motif and homer_motif_batch objects
  - top_n: keep top N per peak set by q-value

APOLLO_get_ppi(genes, organism, resources, min_resources, directed, verbose)
  - Fetch PPI network from OmniPath (aggregates STRING, BioGRID, IntAct, etc.)
  - Filters to interactions where both endpoints are in gene list
  - min_resources: require N supporting databases (default 1)
  - Computes degree and betweenness centrality as vertex attributes
  - Returns igraph object with node/edge attributes
  - Isolated query genes included as disconnected nodes
  - Example: graph <- APOLLO_get_ppi(c("TP53", "BRCA1", "EGFR"))

isoform_annotation.R:
----------------------
Runners for the external tools consumed by ARTEMIS_isoform_switch_consequences()
(cpat_file/signalp_file/pfam_file/deeptmhmm_file). Not yet tested end-to-end
against real CPAT/SignalP/HMMER/DeepTMHMM installs (CPAT/SignalP/Pfam
implemented 2026-07-08, DeepTMHMM added 2026-07-14; user installing tools
locally). Basilisk env declarations live in GAIA/R/basilisk.R.

APOLLO_extract_isoform_sequences(switch_result, genome_object, output_dir,
                                  only_switching_genes, verbose)
  - Required first step before any of the three runners below
  - Wraps IsoformSwitchAnalyzeR::extractSequence()
  - genome_object MUST be a BSgenome object (extractSequence() hard-requires
    class "BSgenome" -- a plain genome FASTA path is not accepted)
  - alpha/dIFcutoff always pulled from switch_result$params (not overridable
    here) to stay consistent with what was already called significant
  - Returns switch_result with $sequence_files$nt_fasta/$aa_fasta added, and
    $switch_list updated (sequences cached in the switchAnalyzeRlist too)

APOLLO_run_cpat(switch_result, hexamer_file, logit_model_file, output_dir,
                 nt_fasta, verbose)
  - Runs CPAT (coding potential) inside the .gaia_cpat_env basilisk env
  - hexamer_file/logit_model_file are explicit paths (species-specific CPAT
    reference files) -- not bundled/auto-fetched, no hardcoded default
    location (project scripts point these at data/isoform_switch_files/)
  - IMPORTANT: CPAT's own output columns (ID, mRNA, ORF_strand, ORF_frame,
    ORF_start, ORF_end, ORF, Fickett, Hexamer, Coding_prob) do NOT match what
    IsoformSwitchAnalyzeR::analyzeCPAT() parses -- confirmed by reading
    analyzeCPAT()'s source. This function reformats CPAT's raw
    *.ORF_prob.best.tsv (falls back to *.ORF_prob.tsv) into the exact
    6-column layout analyzeCPAT() requires (mRNA_size, ORF_size,
    Fickett_score, Hexamer_score, coding_prob, id -- order matters, checked
    with `==` internally) via .apollo_reformat_cpat()
  - Returns path to the reformatted file, ready for
    ARTEMIS_isoform_switch_consequences(cpat_file = ...)

APOLLO_run_signalp(switch_result, output_dir, aa_fasta, organism, mode, verbose)
  - Runs SignalP 6 inside the .gaia_signalp_env basilisk env
  - SignalP 6 is license-gated (DTU) and not on public PyPI, so the basilisk
    env only provisions a base Python interpreter -- SignalP 6 itself must be
    pip-installed manually, once, from the user's licensed wheel into that
    env (path via basilisk::obtainEnvironmentPath(.gaia_signalp_env)),
    following DTU's install instructions including the separate model-weights
    step. This function checks for the installed executable and stops with
    setup instructions if missing rather than auto-installing.
  - Raw prediction_results.txt used directly, no reformatting needed --
    confirmed analyzeSignalP()'s source natively parses SignalP 6's format
    (detected via a "SignalP-6" header line)
  - Returns path to prediction_results.txt

APOLLO_run_pfam(switch_result, pfam_dir, output_dir, aa_fasta, nproc, verbose)
  - Runs pfam_scan.pl (Perl wrapper around HMMER's hmmscan), NOT raw hmmscan
    directly -- IMPORTANT: analyzePFAM() expects pfam_scan.pl's specific
    output format (confirmed against ISAS's own bundled example file), raw
    hmmscan --domtblout output is not compatible
  - Runs inside the .gaia_pfam_env basilisk env (bioconda's `pfam_scan`
    recipe bundles pfam_scan.pl + HMMER + the Bio::Pfam::Scan Perl module as
    conda-declared dependencies, so no manual PfamScan.tar.gz/CPAN setup is
    needed). basilisk is not Python-specific -- it's a general reproducible
    conda-env manager; this env just happens to carry a Perl/native-binary
    tool instead of a Python package, same pattern as CPAT/SignalP otherwise
    (resolve pfam_scan.pl from dirname(reticulate::py_exe())'s bin dir,
    system2() it directly)
  - pfam_dir must contain a pre-pressed (hmmpress) Pfam-A.hmm + Pfam-A.hmm.dat
  - Returns path to pfam_results.txt

APOLLO_run_deeptmhmm(switch_result, deeptmhmm_dir, output_dir, aa_fasta, verbose)
  - Runs DeepTMHMM (cell-membrane topology: intracellular/TM helix/
    extracellular) inside the .gaia_deeptmhmm_env basilisk env
  - DeepTMHMM is academically licensed (DTU Health Tech/BioLib), not on
    PyPI/bioconda -- licensed copy already obtained by user, extracted to
    to_process/DeepTMHMM-Academic-License-v1.0/DeepTMHMM-Academic-License-v1.0/
    (predict.py + 5 deeptmhmm_cv_*.model weight files). Its own
    requirements.txt pins torch==1.5.0+cu92 (CUDA 9.2-era) -- unverified
    whether this resolves on current hardware/drivers, may need a newer
    torch build; the basilisk env only provisions base Python 3.8, torch/deps
    must be installed manually into it once, same pattern as SignalP 6.
  - IMPORTANT (differs from CPAT/SignalP/Pfam): predict.py loads its model
    weights and utils/experiments.tmhmm3.tm_util modules via bare relative
    paths/imports, so it MUST be run with deeptmhmm_dir as cwd -- this
    function temporarily setwd()s into deeptmhmm_dir (restored via on.exit).
    predict.py also refuses to run if output_dir already exists (exits with
    an error) -- this function does not pre-create output_dir, unlike the
    other three runners.
  - Returns path to TMRs.gff3, ready for
    ARTEMIS_isoform_switch_consequences(deeptmhmm_file = ...), which adds the
    "isoform_topology" consequence type (not the related
    extracellular/intracellular_region_count/length types -- call
    IsoformSwitchAnalyzeR::analyzeSwitchConsequences() directly for those)
