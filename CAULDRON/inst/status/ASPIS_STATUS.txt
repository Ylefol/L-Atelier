ASPIS_plot_propeller(propeller_result, palette=NULL, ncol=NULL,
                      point_size=2.5, jitter_width=0.08, show_stats=TRUE,
                      stat_label=c("fdr","pvalue"),
                      order_by=c("significance","cluster"), title=NULL)
  - Added 2026-07-20. Renders a KERAUNOS_propeller_proportions() result:
    one facet per cluster, points = per-sample proportion (coloured by
    group, jittered), grey crossbar = group mean, FDR/p-value annotated
    top-left of each facet
  - Deliberately NOT a boxplot -- with as few as 2 samples/group (e.g.
    Nico_midbrain), boxplot quartiles are degenerate/misleading; points +
    mean crossbar show exactly what was tested
  - Reads only propeller_result$proportions/$results/$params -- no sce
    needed (computation lives entirely in KERAUNOS, per architecture)
  - order_by="significance" (default): facets ordered by ascending P.Value,
    matching propeller_result$results row order
  - palette: NULL resolves via .aspis_resolve_palette() -- uses
    propeller_result$params$group_colors if it was supplied to
    KERAUNOS_propeller_proportions(), else .aspis_discrete_palette()
    (shared helper, same set as ASPIS_plot_umap)
  - Returns ggplot object

ASPIS_plot_composition(propeller_result, palette=NULL, facet_by_group=TRUE,
                        title=NULL)
  - Added 2026-07-20. Fulfils the previously-planned ASPIS_plot_composition
    TODO. 100% stacked bar chart of a KERAUNOS_propeller_proportions()
    result: one bar per sample, cluster proportions stacked to the full bar
    height (geom_col(position="fill")) -- makes the compositional sum-to-1
    constraint visible, which ASPIS_plot_propeller's per-cluster facets
    deliberately do not
  - Complements, does not replace, ASPIS_plot_propeller: this shows the
    whole-composition picture, that one shows the per-cluster statistical
    test result
  - Reads only propeller_result$proportions/$results$baseline_prop/$params
    -- no sce needed, same as ASPIS_plot_propeller
  - Cluster stacking order: largest overall baseline_prop at the bottom
    (stable reference ordering, independent of which group comparison ran --
    unlike ASPIS_plot_propeller's significance-based facet order)
  - facet_by_group=TRUE (default): facet_grid(~group, scales="free_x",
    space="free_x") so samples are grouped visually by experimental group
    rather than arbitrary order
  - palette: NULL resolves via .aspis_resolve_palette() -- uses
    propeller_result$params$cluster_colors if it was supplied to
    KERAUNOS_propeller_proportions(), else .aspis_discrete_palette()
    recycled via rep_len() if more clusters than palette colours (20)
  - Full legend kept by default (one entry per cluster) -- may need
    trimming/relabelling for datasets with many more than ~11 clusters;
    revisit once assessed against real output
  - Added 2026-07-20: legend entries are two lines, "<cluster>\nFDR = <FDR>",
    from the same propeller test -- carries statistical context into the
    composition plot without cross-referencing ASPIS_plot_propeller. Widened
    legend.key.height/legend.spacing.y + guide_legend(byrow=TRUE) + per-entry
    bottom margin on legend.text so two-line entries don't crowd each other
  - Returns ggplot object

ASPIS_plot_qc(sce, metrics=c("sum","detected","subsets_mt_percent"),
              group_by=NULL, thresholds=NULL, log_scale=c("sum","detected"),
              show_points=TRUE, max_points=5000, point_size=0.3,
              point_alpha=0.3, ncol=NULL)
  - Violin + jitter plot of per-cell QC metrics from AEGIS_compute_qc_metrics
  - metrics: any numeric colData column; defaults cover the key AEGIS outputs
      sum                  — total UMI count (log-scaled by default)
      detected             — number of detected genes (log-scaled by default)
      subsets_mt_percent   — % mitochondrial counts (linear scale)
      subsets_ribo_percent — % ribosomal counts (linear scale, if present)
  - group_by: splits violins by a colData column (e.g. sample_id, condition)
  - thresholds: named list draws red dashed lines at filtering cut-offs
    (on the original scale; function handles log transform internally)
  - log_scale: metrics to display as log10(x+1); axis labels updated
  - show_points: jitter overlay; auto-subsampled to max_points cells
  - Requires AEGIS_compute_qc_metrics() to have been run first

ASPIS_plot_elbow(sce, n_show=50, n_pcs=NULL, show_cumulative=TRUE,
                  suggest=NULL, cum_threshold=80)
  - Elbow plot of % variance explained per PCA component
  - Bars + blue points: individual variance; red dashed: cumulative
  - n_pcs: grey dashed line marking the user's chosen cut-off
  - suggest: algorithmic suggestions drawn as distinct coloured lines +
    printed to console
      "elbow"      — green dot-dash: PC of maximum second derivative
                     (sharpest deceleration in the drop-off)
      "cumulative" — purple dot-dash: minimum PCs for >= cum_threshold%
                     total variance (default 80%)
      "both"       — both suggestions shown simultaneously
  - Requires TALOS_run_pca() to have been run first
  - Returns ggplot object

ASPIS_plot_umap(sce, colour_by="cluster", point_size=0.8, point_alpha=0.6,
                 palette=NULL, title=NULL, label_clusters=FALSE,
                 label_size=4, assay_name="logcounts")
  - UMAP scatter plot coloured by colData column or gene expression
  - colour_by auto-detected: colData column (discrete → categorical palette,
    continuous → gradient) or gene name (logcounts → grey-to-blue gradient)
  - label_clusters=TRUE overlays bold centroid labels (discrete only)
  - palette: colour vector for discrete, c(low, high) for continuous/gene;
    NULL uses built-in 20-colour Tableau-inspired set or grey→blue gradient
  - Axis ticks/text removed by default (standard for embedding plots)
  - Requires TALOS_run_umap() to have been run first

ASPIS_plot_tsne(sce, colour_by="cluster", point_size=0.8, point_alpha=0.6,
                 palette=NULL, title=NULL, label_clusters=FALSE,
                 label_size=4, assay_name="logcounts")
  - tSNE scatter plot; identical interface to ASPIS_plot_umap
  - Requires TALOS_run_tsne() to have been run first

ASPIS_plot_embedding_grid(sweep, sce, colour_by="cluster", point_size=0.3,
                           point_alpha=0.5, palette=NULL, assay_name="logcounts")
  - Grid of embedding plots from a talos_embedding_sweep object
    (TALOS_tune_umap or TALOS_tune_tsne output)
  - Reads pre-computed embeddings from sweep$embeddings (no re-computation)
  - UMAP: laid out as n_neighbors × min_dist grid (ncol = n min_dist values)
  - tSNE: row(s) of perplexity panels (ncol = min(3, n_perplexity))
  - Best combination marked with ★ in panel title
  - colour_by: colData column (cluster, region, condition, etc.) or gene name;
    discrete → categorical palette; continuous/gene → gradient
  - Requires talos_embedding_sweep object; works for both UMAP and tSNE

ASPIS_plot_atlas_v5(sce, colour_by, dimred=c("UMAP","tSNE"),
                     # scatter
                     style=c("points","contour","both"), point_size=0.5,
                     point_alpha=0.5, ring_palette=NULL,
                     label_clusters=FALSE, label_size=3,
                     n_levels=8, contour_alpha=0.7,
                     boundary_pad=0.10, inner_pad=0.25,
                     # layout
                     gap_degrees=2, inner_scale=0.95,
                     # label track (outermost)
                     show_label_track=FALSE, label_track_height=0.12,
                     label_track_cex=0.55, label_track_col="black",
                     label_track_font=1L,
                     # colour ring
                     show_ring=TRUE, ring_height=0.15, ring_labels=TRUE,
                     ring_label_cex=0.65, ring_label_col="white",
                     ring_gap=0.01, ring_border_col=NA,
                     min_seg_frac=NULL, bottom_gap_degrees=15,
                     # metadata track labels
                     show_meta_labels=FALSE, meta_label_names=NULL,
                     meta_label_cex=0.65, meta_label_col="black",
                     meta_label_lwd=0.5,
                     # dendrogram
                     show_dendrogram=TRUE, dend_height=0.15,
                     dend_n_pcs=20, dend_max_cells=500,
                     dend_col="grey30", dend_lwd=0.5,
                     # binning
                     n_bin=NULL,
                     # metadata tracks
                     meta_col=NULL, meta_assay="logcounts",
                     meta_palette=NULL, meta_height=0.04,
                     meta_style=c("dot","dot_border","heatmap"),
                     meta_cex=0.3, meta_border_col="white",
                     meta_border_lwd=0.3, meta_scale_q=c(0,1),
                     # output
                     output_file=NULL, width=8, height=8, res=150)
  - Full circos atlas: label track → metadata tracks → colour ring →
    dendrogram → central UMAP/tSNE scatter (grid viewport)
  - ring_palette: colours for colour_by categories; applied consistently to
    scatter AND ring segments (always match)
  - Metadata tracks (meta_col): one ring per entry, outside→inside order
      - discrete colData column → majority-vote per bin, categorical palette
      - numeric colData column  → per-bin mean, colour gradient
      - gene name (rownames)    → per-bin mean expression, colour gradient
      meta_style: "dot" | "dot_border" (pch=21) | "heatmap" (circos.rect)
      meta_scale_q: quantile clipping for continuous tracks e.g. c(0, 0.95)
        prevents sparse-gene colour scales from washing out (default c(0,1))
      meta_border_col=NULL/NA → no border on heatmap tiles or dot outlines
  - Colour ring: proportional arc width; ring_border_col auto-inherits
    meta_border_col when meta_style="heatmap" and ring_border_col=NA
  - min_seg_frac: floor on sector arc fraction; uses sector.width in
    circos.initialize() so xlim (dendrogram/dot x-axis) is unaffected
  - bottom_gap_degrees: fixed large gap at 6 o'clock (270°); overrides the
    embedding-alignment start.degree; sector ORDER from embedding is preserved
  - show_meta_labels: draws track labels + short ticks in the bottom gap at
    each track's radial level; meta_label_names overrides display text
  - show_label_track: outermost text track; labels wrapped via strwrap()
    using arc-width estimate (~2.2 chars/degree); multi-line support
  - n_bin: bin cells by PC1, hclust on bin centroids; all tracks share
    the same leaf order so dots/dendrogram always align
  - Sector order: embedding centroid angle CW from top; start.degree
    optimised by circular mean to mirror the embedding layout
  - Requires circlize; grid viewport overlay for central scatter

ASPIS_plot_atlas(sce, colour_by, dimred=c("UMAP","tSNE"),
                  # scatter
                  style=c("points","contour","both"), point_size=0.5,
                  point_alpha=0.5, ring_palette=NULL,
                  label_clusters=FALSE, label_size=3,
                  n_levels=8, contour_alpha=0.7,
                  boundary_pad=0.10, inner_pad=0.25,
                  # layout
                  gap_degrees=2, inner_scale=0.95,
                  # label track (outermost)
                  show_label_track=FALSE, label_track_height=0.12,
                  label_track_cex=0.55, label_track_col="black",
                  label_track_font=1L,
                  # colour ring
                  show_ring=TRUE, ring_height=0.15, ring_labels=TRUE,
                  ring_label_cex=0.65, ring_label_col="white",
                  ring_gap=0.01, ring_border_col=NA,
                  min_seg_frac=NULL, bottom_gap_degrees=15,
                  # metadata track labels
                  show_meta_labels=FALSE, meta_label_names=NULL,
                  meta_label_cex=0.65, meta_label_col="black",
                  meta_label_lwd=0.5,
                  # scatter labels
                  label_clusters=FALSE, label_size=3,
                  label_split=FALSE, label_split_min_sil=0.35,
                  label_split_k_max=5, label_split_size_scale=TRUE,
                  label_split_size_range=NULL, label_split_min_cells=50L,
                  label_split_nudge=0, label_split_angle=TRUE,
                  # dendrogram
                  show_dendrogram=TRUE, dend_height=0.15, dend_clip=1,
                  dend_power=1, dend_n_pcs=20, dend_max_cells=500,
                  dend_col="grey30", dend_lwd=0.5,
                  # binning
                  n_bin=NULL,
                  # metadata tracks
                  meta_col=NULL, meta_assay="logcounts",
                  meta_palette=NULL, meta_height=0.04,
                  meta_style=c("dot","dot_border","heatmap"),
                  meta_cex=0.3, meta_border_col="white",
                  meta_border_lwd=0.3, meta_scale_q=c(0,1),
                  # satellite panels
                  show_satellites=TRUE, sat_col=NULL, sat_custom=list(), sat_size=0.22,
                  sat_point_size=0.3, sat_point_alpha=0.5,
                  show_sat_title=TRUE, sat_title_cex=0.7, sat_title_col="black",
                  # output
                  output_file=NULL, width=8, height=8, res=150)
  - Current primary circos atlas; formerly aspis_atlas_v6.R
  - Full circos atlas: label track → metadata tracks → colour ring →
    dendrogram → central UMAP/tSNE scatter (grid viewport)
  - ring_palette: colours for colour_by categories; applied consistently to
    scatter AND ring segments (always match)
  - Metadata tracks (meta_col): one ring per entry, outside→inside order
      - discrete colData column → majority-vote per bin, categorical palette
      - numeric colData column  → per-bin mean, colour gradient
      - gene name (rownames)    → per-bin mean expression, colour gradient
      meta_style: "dot" | "dot_border" (pch=21) | "heatmap" (circos.rect)
      meta_scale_q: quantile clipping for continuous tracks e.g. c(0, 0.95)
      meta_border_col=NULL/NA → no border on heatmap tiles or dot outlines
  - Colour ring: proportional arc width; ring_border_col auto-inherits
    meta_border_col when meta_style="heatmap" and ring_border_col=NA
  - min_seg_frac: floor on sector arc fraction (xlim/dendrogram unaffected)
  - bottom_gap_degrees: fixed large gap at 6 o'clock via gap.after named vector
  - show_meta_labels: track labels + ticks drawn in bottom gap
  - label_split=TRUE: density-aware sub-cluster labelling via k-means on
    2D embedding coords per category; accepts split if mean silhouette >=
    label_split_min_sil; one label per sub-cluster (same category name);
    label_split_size_range=c(min,max): absolute ggplot size bounds (NULL→c(label_size*0.5, label_size));
    label_split_size_scale: maps sqrt(n_sub/n_cat) linearly across size_range;
    label_split_min_cells: skip category or sub-cluster if n < threshold (default 50);
    label_split_nudge: shift label along PC2 in units of PC2 SD (default 0);
      PC2 oriented to positive-y so positive = upward, negative = downward;
    label_split_angle: text angle from PC1 of cluster's own covariance matrix;
    helper: .aspis_split_labels() in aspis_atlas.R; uses cluster::silhouette()
  - dend_clip (0–1, default 1): zooms into heights 0..clip×max_h,
    stretching that region to fill the track; root clipped at boundary
  - dend_power (>0, default 1): non-linear height transform
    h_new=(h/max_h)^power*max_h before drawing; power<1 (e.g. 0.5)
    compresses the root arch visually while expanding leaf-level forks;
    root stays at max_h (not clipped); try 0.3–0.6 for tall roots
  - Satellite panels (show_satellites): mini-embeddings in device corners
    (TL, TR, BL, BR); same embedding as central, coloured by sat_col entries
    sat_col: subset of meta_col (NULL = first 4); capped at 4
    Colour scale matches circos track; transparent background
    show_sat_title=FALSE hides the per-satellite title
    sat_size=0.22 fits in default R margin area outside the outermost ring
    sat_legend: FALSE/TRUE/character vector — controls which sats show legends
    sat_legend_max_cats=10: auto-suppress discrete legends with >N categories
    sat_legend_title_cex / sat_legend_text_cex: legend text sizes
    Legend layout (semi-asymmetric):
      TL/TR: legend below satellite, left/right-pinned (hangs down)
      BL/BR: legend on inner edge, toward centre (points inward)
    Helper: .aspis_sat_legend_grob() extracts guide-box via ggplotGrob()$layout
    sat_custom: named list (names "TL"/"TR"/"BL"/"BR" only), values a ggplot
      object to draw in that corner INSTEAD of a sat_col-driven scatter --
      escape hatch for satellite content that isn't a simple metadata/gene
      scatter (e.g. ASPIS_plot_velocity_stream() output). Named corners are
      claimed first; remaining corners still fill from sat_col_use in
      TL/TR/BL/BR order. Only structural chrome (panel border, background,
      margin) is stripped from a sat_custom plot to match the other
      satellites -- its own title/legend are left as supplied, since there is
      no metadata track here to derive a title or auto-legend from (a
      sat_legend entry has no effect on a sat_custom corner)
  - Requires circlize; grid viewport overlay for central scatter + satellites

ASPIS_plot_db_heatmap(sce, markers, cluster_col="cluster",
                       assay_name="logcounts", scale=TRUE,
                       na_color="grey80", palette=NULL,
                       show_gene_labels=TRUE, title="Marker database heatmap")
  - Heatmap of genes from a user-supplied marker database (e.g. ScTypeDB)
  - markers: data.frame with columns cell_type, markers (comma-separated),
    and optional neg_markers (comma-separated)
  - Rows = database genes, faceted by cell_type; cols = clusters
  - Genes absent from the SCE shown as grey NA tiles (na_color)
  - When neg_markers column present, positive/negative shown as nested
    sub-facets within each cell_type via facet_grid(cell_type + marker_type)
  - Reports total/found/missing gene counts + missing gene names via cat()
  - Returns ggplot object

ASPIS_plot_marker_dotplot(sce, markers, cluster_col="cluster",
                           assay_name="logcounts", top_n=5L, scale=TRUE,
                           min_expr=0, dot_max_size=6, palette=NULL,
                           title="Marker genes")
  - Dot plot: size = % cells expressing, fill = scaled (z-scored) mean expr
  - markers: keraunos_markers object OR character vector of gene names
  - Genes ordered by source cluster; dashed hlines separate cluster groups
  - scale=FALSE plots raw mean expression instead of z-scores
  - palette: custom gradient colours; NULL = blue-white-red diverging
  - Returns ggplot object

ASPIS_plot_marker_heatmap(sce, markers, cluster_col="cluster",
                           assay_name="logcounts", top_n=5L, scale=TRUE,
                           palette=NULL, show_gene_labels=TRUE,
                           title="Marker gene heatmap")
  - Cluster-averaged expression heatmap (genes × clusters)
  - markers: keraunos_markers object → genes faceted by source cluster
             character vector → no faceting, genes shown in supplied order
  - scale=TRUE: z-scores expression per gene across clusters (default)
  - Facets via facet_grid(source_cluster ~ ., free_y, switch="y") when source
    cluster info is available
  - show_gene_labels=FALSE hides y-axis text (useful for many genes)
  - Returns ggplot object

- File structure:
    aspis_composition.R — ASPIS_plot_propeller (cell-type proportion test
                          result), ASPIS_plot_composition (100% stacked bar);
                          shared internal helper .aspis_resolve_palette()
                          (explicit palette arg > propeller_result$params
                          cluster_colors/group_colors > .aspis_discrete_palette()
                          default -- see KERAUNOS_propeller_proportions())
    Fixed 2026-07-20: .aspis_resolve_palette() unconditionally called
    rep_len(pal, length(levels)) before checking/assigning names. rep_len()
    silently DROPS names even when the length is already correct (confirmed:
    rep_len(c(a=1,b=2),2) -> unnamed c(1,2)). So a correctly-named
    cluster_colors/group_colors map lost its names, then got renamed
    POSITIONALLY to `levels` (which is usually in a DIFFERENT order --
    ASPIS_plot_composition's cluster_order is sorted by descending
    baseline_prop, not the colour map's own order) -- silently scrambling
    which colour landed on which category, while each colour still looked
    individually "valid" (a real hex code, just paired with the wrong
    label). Reported as: ASPIS_plot_propeller "worked" (it only colours by
    group_col, 2-3 levels, one case that happened to still look right) but
    ASPIS_plot_composition (colours by cluster_col fill, ~11 cell_label
    levels) visibly did not -- e.g. the colour for "Astrocyte_1" also
    appeared next to "Immature Neuron" and "Precursor Neuron" in the legend.
    Diagnosed via ggplot2::get_guide_data(plot, "fill") comparing .value
    (category) against fill (rendered colour) directly -- scale$palette()
    alone did not surface it. Fixed: only rep_len()+rename when the incoming
    palette has NO names to begin with (the genuine recycle case, e.g. the
    default 20-colour set extended for >20 clusters); an already-named
    palette skips straight to pal[levels], a real by-name lookup. Regression-
    tested: default unnamed recycled palette (12 clusters) and
    ASPIS_plot_propeller's group_colors both still correct after the fix.
    aspis_embedding.R — elbow, UMAP, tSNE, embedding_grid, QC plots;
                        shared helpers (.aspis_plot_dimred,
                        .aspis_dynamic_contours, .aspis_discrete_palette)
    Changed 2026-07-21: .aspis_plot_dimred()'s and ASPIS_plot_embedding_grid()'s
    discrete colour-scale branches now call the shared .aspis_resolve_palette()
    (aspis_composition.R) instead of their own rep(palette, length.out=n_lev)
    logic -- consistency cleanup (this rep() form does preserve names, unlike
    rep_len(), so it was not itself broken; investigated as a suspect while
    chasing the .aspis_discrete_palette() bug below and kept as the single
    source of truth for palette resolution across ASPIS).
    Fixed 2026-07-21: .aspis_discrete_palette() used to be its own
    independently hand-copied 20-colour list, separate from KHALKOS's
    .khalkos_cat_palette_20 (see KHALKOS_STATUS.txt) -- the two agreed on
    positions 1-10 but diverged from 11 onward. Any plot using an explicit
    KHALKOS_assign_metadata_colours() map disagreed with any plot left at
    its un-styled default (palette=NULL) for every category past the 10th.
    Root-caused from real report data: colours$cluster (KHALKOS-built) said
    cluster 11 = #1F77B4 (blue); the historical UMAP png (rendered with no
    palette=, i.e. .aspis_discrete_palette()'s old list) showed cluster 11
    as #79706E (dark grey/brown). Confirmed by running the actual current
    source end-to-end against a synthetic SCE matching the report's real
    16-cluster sizes -- KHALKOS's list and a KHALKOS-driven ASPIS_plot_umap()
    call matched perfectly, which correctly ruled out a level-ordering bug
    and pointed at the two hardcoded palettes themselves differing. Fixed by
    making .khalkos_cat_palette_20 canonical (updated to match the values
    users' existing historical plots were already anchored on) and having
    .aspis_discrete_palette() delegate to KHALKOS_default_palette(20,
    "categorical") instead of duplicating the list, so the two can't drift
    apart again. Affects every ASPIS function using .aspis_discrete_palette()
    as its no-palette-supplied default: ASPIS_plot_umap/tSNE/embedding_grid,
    ASPIS_plot_atlas, ASPIS_plot_propeller/composition, trajectory plots.
    aspis_atlas.R     — ASPIS_plot_atlas; current primary atlas function
                        (circlize ring + tracks + corner satellites)
    aspis_atlas_v2.R  — ASPIS_plot_atlas_v2; kept for reference
    aspis_atlas_v3.R  — ASPIS_plot_atlas_v3; kept for reference
    aspis_atlas_v4.R  — ASPIS_plot_atlas_v4; kept for reference
    aspis_atlas_v5.R  — ASPIS_plot_atlas_v5; kept for reference
